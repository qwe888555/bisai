### 2.2 命令设计（建议形态，成员2 域，开发前须其确认或授权）

| 项 | 设计 |
|---|---|
| 位置 | `apps/accounts/management/commands/init_admin.py` |
| --username | 必填或默认 `admin`；唯一性校验**含软删行**（避免踩 Organization 软删重建同型缺陷） |
| 密码来源 | 三选一，优先级：`--password-stdin` > 环境变量 `ADMIN_INIT_PASSWORD` > 交互 getpass；**禁止 `--password` 明文命令行参数**（shell history 泄漏） |
| 创建 | `Account.objects.create(id=new_account_id(), username=…, display_name=…, roles=["ADMIN"], password=make_password(pw), enabled=True, must_change_password=True)` |
| 组织挂载 | 依赖 #5 裁决：方案A（无组织 ADMIN）→ 不挂组织；方案B → 须同时提供 `--org` 或要求预置根组织，否则拒绝执行 |
| 幂等 | 执行前检查任意 `roles` 含 ADMIN 的账号（含软删）已存在 → 拒绝、非零退出码 |
| 审计 | `AuditLog(log_type="OPERATION", action="admin.init", object_type="Account", object_id=新账号ID, operator_account_id=新账号ID, outcome="SUCCESS", summary=…)`；失败不落号不落审计 |
| 输出 | 创建成功仅打印账号 ID 与"首次登录须改密"提示，**不回显密码** |

### 2.3 测试方案（内存库，全部可先行编写）

1. 成功创建：roles=[ADMIN]、must_change_password=True、AuditLog 行存在、首次登录返回 mustChangePassword=True；

3. 弱密码：按策略拒绝、不落库；

## 三、开发/生产配置隔离分析（任务4，只形成分析）

### 3.1 现状（config/settings.py 实码）

- env helper 体系已在（env/env_bool/env_list，L32-51），设计哲学"所有可变项走环境变量、同一套代码"（L4-5）；`DATABASE_URL` 可切生产组件，默认 SQLite 零依赖启动（L138）；
- **安全默认值仍在**（生产风险）：
  - `DJANGO_SECRET_KEY` 默认 `"dev-only-change-me-please-32bytes-min"`（L64）；
  - `DEBUG` 默认 **True**（L65）；
  - `ALLOWED_HOSTS` 默认 `"*"`（L66）；
  - `JWT_SECRET` 默认=SECRET_KEY（L180）；
  - 身份证/手机号 AES-GCM 主密钥**可由 JWT_SECRET 派生**（L182 注释自述"仅开发便利"）；
  - `MINIO_SECRET_KEY` 默认 `"minioadmin"`（L197）。

### 3.2 风险评估

| 默认项 | 生产后果 |
|---|---|
| SECRET_KEY 默认值 | 可伪造签名/JWT（JWT_SECRET 又默认同源） |
| 字段加密主密钥派生自 JWT_SECRET | 密钥同源放大：一处泄露=JWT 伪造+证件密文可解 |
| DEBUG=True | 错误页泄露配置与源码路径 |
| ALLOWED_HOSTS=* | Host 头注入风险 |
| MINIO minioadmin | 对象存储弱凭据 |

### 3.3 拆分方案对比（供拍板，不改动）

| 方案 | 内容 | 代价 |
|---|---|---|
| A：拆文件 | `config/settings/{base,dev,prod}.py` + `DJANGO_SETTINGS_MODULE` 切换；base 收敛公共项，dev 保留便利默认，**prod 无任何密钥默认值（缺失即启动失败）+DEBUG 强制 False+ALLOWED_HOSTS 必填** | 目录结构调整、wsgi/manage.py 默认值变更；与现"同一套代码"哲学兼容（仍是 env 驱动） |
| B：单文件+生产强制校验 | 保持现单文件，新增 `DJANGO_ENV=production` 开关：该模式下密钥缺默认、DEBUG 拒绝 True、HOSTS 拒绝 * | 改动最小；逻辑分支集中在单文件，长期可读性略差 |

两案均**保留 dev 零配置启动**（现设计优点），差别只在生产强制力的实现位置。建议 A（与部署验收 D8-D10 直接对应），B 可作过渡；最终由成员2/组长定，**本轮不改任何配置代码**。

### 3.4 生产环境变量清单（建议）

`DJANGO_SECRET_KEY`（强制）、`JWT_SECRET`（建议独立）、字段加密主密钥（建议独立显式，替代派生）、`DATABASE_URL`、`REDIS_URL`、`MINIO_*`、`ALLOWED_HOSTS`（必填）、`DJANGO_DEBUG=False`、未来 `ADMIN_INIT_PASSWORD`（若保留，见 §2.4-2）。
