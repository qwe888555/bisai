## 通用约定

### 响应信封

独立运行：

```json
{ "code": 0, "message": "ok", "data": {} }
```

失败示例：

```json
{ "code": 409, "message": "该报名信息已在公示中", "data": null }
```

并入主程序后自动切换为主程序信封：

```json
{ "code": "OK", "message": "成功", "data": {}, "requestId": "req_..." }
```

失败时 `code` 为主程序错误码（`INVALID_ARGUMENT`、`NOT_FOUND`、`STATE_CONFLICT`、`UNAUTHENTICATED` 等）。Excel 导出接口成功时直接返回文件流，不使用该信封。

### 认证

- 独立演示：没有登录鉴权；写操作通过请求头记录审计用户：

```http
X-User-Id: 1
```

- 该值只写入 `created_by`、`updated_by`、`published_by`、`cancelled_by`、`generated_by`，默认空字符串。
- 并入主程序（`SELECTION_AUTH_MODE=auto`）后，管理接口自动要求成员2签发的 JWT：

```http
Authorization: Bearer <accessToken>
```

- 未登录管理接口返回 HTTP 401 + `code=UNAUTHENTICATED`。
- 门户公示列表、门户公示详情、市州选项免登录（显式 `auth=None`）。
- `X-User-Id` 可伪造，只适合本地演示。

### 错误码

| HTTP / code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误、业务校验失败、数据不匹配 |
| 404 | 模板、评分、结果、公示记录或报名档案不存在 |
| 405 | 请求方法不支持 |
| 409 | 重复录入、并发修改、结果已过期 |
| 500 | 服务器内部错误或适配器配置错误 |

### 分页

分页接口使用查询参数：

| 参数 | 默认值 | 约束 |
|---|---|---|
| `page` | 1 | 最小 1 |
| `size` | 10 | 最小 1，最大 100，超过 100 按 100 处理 |

独立运行时分页返回：

```json
{ "records": [], "total": 0, "page": 1, "size": 10 }
```

并入主程序后自动切换为主程序分页结构：

```json
{ "items": [], "page": 1, "pageSize": 10, "total": 0 }
```

前端可以用 `records ?? items` 兼容两种结构。

### 字段与时间

- 请求体字段同时接受 `snake_case` 和 `camelCase`，例如 `event_id` / `eventId`、`group_type` / `groupType`。
- 响应字段统一使用 `snake_case`。
- 时间格式：`YYYY-MM-DD HH:MM:SS`，时区 `Asia/Shanghai`。
- 赛事 ID、球员档案 ID、报名档案 ID、操作人 ID 统一按**字符串**传递和返回，例如独立演示的 `"1"`、`"10001"`，主程序的 `"evt_..."`、`"rst_..."`、`"acc_..."`。前端不要用 `parseInt` 处理。
- 分数、权重、综合分按浮点数返回，保留两位小数。
- 所有 URL 以 `/` 结尾。
- JSON 请求使用 `Content-Type: application/json`，编码 UTF-8。

### 通用规则

- `NinjaAPI` 默认 `csrf=False`，便于接口工具直接调用。
- 模板创建后不能修改组别和轮次。
- 评分修改、结果生成等写操作由服务端做并发控制，冲突返回 409。
- 评分新增或修改后，当前有效结果批次会被标记为 `stale=true`。
- 结果导出遇到 `stale=true` 返回 409，必须重新生成。
- 公示取消为软取消，不删除记录；取消后门户立即不可见，CMS 仍可审计。

## 1. 评分模板（4 个）

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 1 | GET | `/templates/` | 查询模板列表 |
| 2 | POST | `/templates/` | 新建模板 |
| 3 | GET | `/templates/{templateId}/` | 模板详情 |
| 4 | PUT | `/templates/{templateId}/` | 修改模板 |

查询参数（#1）：`group_type`、`round`、`status`（均可选；`status=1` 启用，`0` 停用）

请求体（#2 创建）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 模板名称，最长 100 |
| group_type | enum | 是 | HIGHER/MIDDLE/PRIMARY |
| round | enum | 是 | INITIAL/FINAL |
| items | array | 是 | 评分维度，1–20 个 |
| items[].dimension_code | string | 是 | 维度编码，最长 32，自动转大写 |
| items[].dimension_name | string | 是 | 维度名称，最长 64 |
| items[].weight | number | 是 | 权重，0.01–100 |
| items[].max_score | number | 否 | 维度满分，默认 100，必须大于 0 |
| items[].sort_no | int | 否 | 排序号，默认按数组顺序 |

规则：

- 所有维度权重之和必须**严格等于 100**。
- 同一模板内维度编码不能重复。
- 新建模板时，同组别、同轮次、状态为启用的旧模板会自动停用。
- 历史评分使用自己的维度快照，不受模板停用影响。
- 修改模板时 `group_type`、`round` 只能传原值，不能修改；`items` 传入后整体替换原维度。
- 只传 `name` 时仅修改名称。

请求示例（#2）：

```json
{
  "name": "高校组初选评分模板",
  "group_type": "HIGHER",
  "round": "INITIAL",
  "items": [
    { "dimension_code": "TECH", "dimension_name": "技术能力", "weight": 30, "max_score": 100 },
    { "dimension_code": "MATCH", "dimension_name": "比赛表现", "weight": 30, "max_score": 100 },
    { "dimension_code": "PHYSICAL", "dimension_name": "身体素质", "weight": 20, "max_score": 100 },
    { "dimension_code": "TACTIC", "dimension_name": "战术意识", "weight": 20, "max_score": 100 }
  ]
}
```

响应字段（template_out）：id, name, group_type, group_type_label, round, round_label, status, created_by, created_at, updated_at, items

items 元素：id, dimension_code, dimension_name, weight, max_score, sort_no

主要错误：

| 状态码 | 场景 |
|---|---|
| 400 | 名称为空、维度为空、权重和不为 100、维度重复、组别/轮次非法 |
| 404 | 模板不存在 |

## 2. 评分录入与查询（6 个）

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 5 | GET | `/scores/` | 分页查询评分 |
| 6 | POST | `/scores/` | 录入评分 |
| 7 | GET | `/scores/{scoreId}/` | 评分详情 |
| 8 | PUT | `/scores/{scoreId}/` | 修改评分 |
| 9 | GET | `/scores/summary/` | 单轮汇总排名 |
| 10 | GET | `/scores/export/` | 导出评分 Excel |

查询参数（#5）：`event_id`（必填）、`group_type`（必填）、`round`（必填）、`keyword`（可选，姓名/球队模糊搜索）、`page`、`size`

列表排序：总分降序 → 球员档案 ID 升序。

请求体（#6 录入）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| event_id | string | 是 | 赛事 ID，例如 `"1"`；主程序为 `evt_...` |
| group_type | enum | 是 | HIGHER/MIDDLE/PRIMARY（也接受 UNIVERSITY 作为 HIGHER 的别名） |
| round | enum | 是 | INITIAL/FINAL |
| template_id | int | 是 | 评分模板 ID（本模块自增主键） |
| candidate_id | string | 是 | 球员档案 ID，例如 `"10001"`；主程序为运动员 Person ID |
| scores | array | 是 | 维度得分数组 |
| scores[].dimension_code | string | 是 | 维度编码，必须与模板一致 |
| scores[].score | number | 是 | 维度得分，0 到该维度满分 |

规则：

- 模板必须存在且处于启用状态。
- 模板的组别、轮次必须与请求一致。
- 请求中的维度必须与模板维度**完全一致**，不能缺少或多余。
- 同一赛事、同一轮次、同一球员只能有一条评分。
- 球员档案必须存在，且档案中的赛事、组别与请求一致。
- 录入成功后，该赛事该组别的当前有效结果会被标记为 `stale=true`。

请求示例（#6）：

```json
{
  "event_id": "1",
  "group_type": "HIGHER",
  "round": "INITIAL",
  "template_id": 1,
  "candidate_id": "10001",
  "scores": [
    { "dimension_code": "TECH", "score": 92 },
    { "dimension_code": "MATCH", "score": 88 },
    { "dimension_code": "PHYSICAL", "score": 85 },
    { "dimension_code": "TACTIC", "score": 90 }
  ]
}
```

修改请求体（#8）：

```json
{
  "scores": [
    { "dimension_code": "TECH", "score": 95 },
    { "dimension_code": "MATCH", "score": 90 },
    { "dimension_code": "PHYSICAL", "score": 85 },
    { "dimension_code": "TACTIC", "score": 90 }
  ]
}
```

修改规则：

- 只修改维度得分，不能修改球员、模板、组别、轮次。
- 必须提交当前评分记录的全部维度。
- 每次修改 `version` 加 1。
- 服务端读取当前 `version`，更新时以 `version` 为条件；客户端不需要传 `version`。
- 如果并发请求已经修改了该评分，返回 409。
- 修改成功后，当前有效结果批次会被标记为 `stale=true`。

汇总参数（#9）：`event_id`、`group_type`、`round`（均必填）

汇总排序规则：

1. 总分降序；
2. `SELECTION_TIE_BREAK_DIMENSION_CODE` 指定的维度（默认 `TECH`）得分降序；
3. 球员档案 ID 升序。

响应字段（score_out）：id, event_id, group_type, group_type_label, round, round_label, template_id, candidate_id, candidate_name, team_name, position, total_score, version, created_by, created_at, updated_by, updated_at, items

items 元素：id, dimension_code, dimension_name, weight, max_score, score, sort_no

汇总接口在 score_out 基础上额外返回 `rank_no`。

Excel 导出（#10）：

- 查询参数：`event_id`、`group_type`、`round`
- 返回 `.xlsx` 文件流
- Excel 列：排名、姓名、球队、位置、组别、轮次、各维度得分、总分、评分时间
- 没有可导出数据时返回 404

主要错误：

| 状态码 | 场景 |
|---|---|
| 400 | 参数缺失、模板停用、模板组别/轮次不一致、维度缺失/多余、得分越界、球员档案不存在或组别/赛事不一致 |
| 404 | 模板或评分记录不存在、导出无数据 |
| 409 | 该球员本轮评分已存在、评分已被其他人修改 |

## 3. 遴选结果（4 个）

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 11 | POST | `/results/generate/` | 生成遴选结果（新版本） |
| 12 | GET | `/results/latest/` | 当前有效结果 |
| 13 | GET | `/results/batches/` | 结果历史批次 |
| 14 | GET | `/results/export/` | 导出结果 Excel |

请求体（#11 生成）：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| event_id | string | 是 | - | 赛事 ID，例如 `"1"`；主程序为 `evt_...` |
| group_type | enum | 是 | - | HIGHER/MIDDLE/PRIMARY |
| result_round | enum | 否 | FINAL | 结果依据轮次 INITIAL/FINAL |
| quota | int | 否 | 11 | 遴选名额，最小 1 |
| initial_weight | number | 否 | 0.4 | 初选权重，最小 0 |
| final_weight | number | 否 | 0.6 | 复选权重，最小 0 |

规则：

- `result_round=FINAL`：必须存在复选评分；初选评分可选，缺失时直接使用复选总分；`initial_weight + final_weight` 必须大于 0。
- `result_round=INITIAL`：只使用初选评分；权重内部固定为初选 1、复选 0。
- 每次生成都会创建新版本，旧版本 `active=false`，新版本 `active=true`。
- 生成结果不会清除历史批次。
- 新结果生成后 `stale=false`。
- 并发生成冲突返回 409。

请求示例（#11）：

```json
{
  "event_id": "1",
  "group_type": "HIGHER",
  "result_round": "FINAL",
  "quota": 11,
  "initial_weight": 0.4,
  "final_weight": 0.6
}
```

查询参数（#12）：`event_id`、`group_type`（均必填）

查询参数（#13）：`event_id`、`group_type`（均必填）、`limit`（默认 20，1–100）

查询参数（#14）：`event_id`、`group_type`（均必填）

响应字段（result_batch_out）：id, event_id, group_type, group_type_label, result_round, result_round_label, quota, initial_weight, final_weight, formula_snapshot, version_no, active, stale, generated_by, generated_at, items

items 元素：rank_no, candidate_id, candidate_name, team_name, position, initial_score, final_score, composite_score, detail

detail 结构：

```json
{
  "initial": { "total": 85.9, "items": [] },
  "final": { "total": 91.9, "items": [] }
}
```

历史批次接口返回 result_batch_out 数组，每个批次**不包含 items**，额外包含 `item_count`。

Excel 导出（#14）：

- 返回 `.xlsx` 文件流
- Excel 列：排名、姓名、球队、位置、组别、结果依据、初选总分、复选总分、综合分、生成时间
- 文件末尾额外包含计算规则 `formula_snapshot`、结果批次版本和生成时间
- 尚未生成结果返回 404
- 评分已变更、结果已过期返回 409

主要错误：

| 状态码 | 场景 |
|---|---|
| 400 | 没有可用评分、权重和小于等于 0、参数非法 |
| 404 | 尚未生成结果 |
| 409 | 并发生成冲突、结果已过期 |

## 4. 报名公示（8 个）

| # | 方法 | 路径 | 说明 |
|---|---|---|---|
| 15 | GET | `/publicity/` | 门户公示列表（只返回已公示） |
| 16 | POST | `/publicity/` | 公示一条报名信息 |
| 17 | GET | `/publicity/{recordId}/` | 门户公示详情 |
| 18 | POST | `/publicity/{recordId}/cancel/` | 取消公示 |
| 19 | GET | `/publicity/cities/` | 已公示市州选项 |
| 20 | POST | `/publicity/batch/` | 批量公示 |
| 21 | GET | `/publicity/manage/` | CMS 公示管理列表 |
| 22 | GET | `/publicity/manage/{recordId}/` | CMS 公示详情 |

查询参数（#15）：`event_id`（必填）、`group_type`、`city`、`publicity_type`、`keyword`、`page`、`size`

**门户列表只返回 `status=PUBLISHED` 的记录。** 已取消记录不会出现在门户列表。

请求体（#16 公示）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| event_id | string | 是 | 赛事 ID，例如 `"1"`；主程序为 `evt_...` |
| publicity_type | enum | 是 | ATHLETE/COACH/TEAM |
| source_id | string | 是 | 成员4报名/档案记录 ID，例如 `"10001"`、`"C1001"`、`"T1001"`；主程序为 `rst_...` / `TeamCoach.id` / `enr_...` |

数据流：

```text
请求只提交赛事、公示类型、报名档案 ID
        ↓
从成员4报名档案读取权威数据
        ↓
按公示类型应用字段白名单
        ↓
身份证脱敏
        ↓
写入 sel_publicity
```

前端不能直接提交姓名、身份证等公示内容。

请求示例（#16）：

```json
{
  "event_id": "1",
  "publicity_type": "ATHLETE",
  "source_id": "10001"
}
```

规则：

- 同一赛事 + 公示类型 + 报名档案 ID 唯一。
- 已公示时返回 409。
- 已取消的记录可以重新公示，重新公示会刷新快照并清空取消信息。
- 运动员/教练员档案缺少身份证号时返回 400；球队不需要身份证号。
- 报名档案的赛事、组别、类型必须与请求一致。

返回：管理端公示对象（publicity_manage_out），并额外包含：

| 字段 | 说明 |
|---|---|
| action | `published`（首次公示）或 `republished`（取消后重新公示） |

门户详情（#17）：只返回公开公示对象；记录不存在或已取消返回 404。取消后门户详情立即不可见。

取消请求体（#18，可选）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| reason | string | 否 | 取消原因，最长 200 字符 |

也接受 `cancel_reason` 或 `cancelReason`。

请求示例（#18）：

```json
{ "reason": "报名信息有误，退回修改" }
```

取消规则：

- 取消只把 `status` 改为 `CANCELLED`，不删除记录。
- 记录取消人、取消时间、取消原因。
- 重复取消是幂等的，不会报错。
- 取消后门户列表、详情、市州选项立即不再返回该记录。
- CMS 管理列表和详情仍可查看。

返回：管理端公示对象，并额外包含：

| 字段 | 说明 |
|---|---|
| already_cancelled | `true` 表示本次调用前已经是取消状态 |

查询参数（#19）：`event_id`（必填）、`group_type`、`publicity_type`

返回：字符串数组，例如 `["东林市", "南湖市", "江城市"]`。只统计 `status=PUBLISHED` 的记录。

请求体（#20 批量公示）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| event_id | string | 是 | 赛事 ID，例如 `"1"`；主程序为 `evt_...` |
| group_type | enum | 否 | 组别 |
| publicity_type | enum | 否 | 公示类型 |
| city | string | 否 | 市州 |

规则：

- `group_type`、`publicity_type`、`city` **至少传一个**，避免误公示全部报名信息。
- 已公示的记录会被跳过，不视为失败；已取消的记录会重新公示。
- 接口可以重复调用，适合 CMS 的“一键公示”按钮。
- 单条失败不会中断整个批次，失败信息进入 `errors`。

请求示例（#20）：

```json
{
  "event_id": "1",
  "group_type": "MIDDLE",
  "publicity_type": "COACH"
}
```

返回：

```json
{
  "published": 4,
  "skipped": 1,
  "failed": 0,
  "errors": [],
  "records": []
}
```

| 字段 | 说明 |
|---|---|
| published | 本次新公示数量 |
| skipped | 已公示而跳过的数量 |
| failed | 失败数量 |
| errors | 失败明细，元素包含 `source_id` 和 `message` |
| records | 本次新公示/重新公示的记录数组 |

查询参数（#21）：`event_id`（必填）、`group_type`、`city`、`publicity_type`、`status`（PUBLISHED/CANCELLED）、`keyword`、`page`、`size`

CMS 管理列表返回分页对象，`records` 为管理端公示对象数组，**包含已取消记录**。

CMS 详情（#22）返回管理端公示对象，包含报名档案 ID、公示操作人、取消操作人、取消时间、取消原因、创建/更新时间。

主要错误：

| 状态码 | 场景 |
|---|---|
| 400 | 报名档案赛事/组别/类型不匹配、缺市州、缺姓名/球队名称、缺身份证号、字段格式错误、批量公示未指定任何筛选条件 |
| 404 | 报名档案不存在、公示记录不存在、门户记录已取消 |
| 409 | 该报名信息已在公示中 |
| 500 | 公示数据源未配置或初始化失败 |

## 7. 核心业务规则

### 7.1 单轮总分

```text
维度百分比 = 维度得分 / 该维度满分 × 100
单轮总分 = Σ(维度百分比 × 权重) / Σ(权重)
```

结果保留两位小数，四舍五入。

### 7.2 综合分

```text
综合分 = (初选总分 × 初选权重 + 复选总分 × 复选权重)
         / (初选权重 + 复选权重)
```

- 只有一轮成绩时，直接使用该轮总分。
- 初选结果只使用初选成绩。
- 复选结果要求有复选成绩，初选成绩可选。

### 7.3 同分排序

复选结果：

1. 综合分降序；
2. `TECH` 维度得分降序（可通过 `SELECTION_TIE_BREAK_DIMENSION_CODE` 修改）；
3. 复选总分降序；
4. 初选总分降序；
5. 球员档案 ID 升序。

初选结果：

1. 初选总分降序；
2. `TECH` 维度得分降序；
3. 球员档案 ID 升序。

### 7.4 结果过期

- 评分新增或修改后，当前有效结果批次 `stale=true`。
- 结果导出遇到 `stale=true` 返回 409。
- 重新生成结果会产生新版本，旧版本保留。

### 7.5 身份证脱敏

| 长度 | 规则 | 示例 |
|---|---|---|
| 18 位 | 保留前 6 位和后 4 位，中间替换为 `*` | `510101********0011` |
| 15 位 | 保留前 6 位和后 3 位，中间替换为 `*` | `510101******011` |
| 7–14 位 | 保留前 2 位和后 2 位 | `51******11` |
| 少于 7 位 | 全部替换为 `*` | `***` |

数据库只保存 `id_card_masked`，不保存身份证原文。

### 7.6 公示字段白名单

默认白名单：

```python
SELECTION_PUBLICITY_FIELD_WHITELIST = {
    "ATHLETE": (
        "name", "gender", "id_card", "team_name",
        "school_name", "position", "jersey_number",
    ),
    "COACH": (
        "name", "gender", "id_card", "team_name",
        "school_name", "coach_role",
    ),
    "TEAM": ("team_name", "school_name", "coach_name"),
}
```

- 只有白名单字段会进入公示快照。
- `phone`、`birth_date`、`contact_phone`、`team_type` 等非白名单字段不会落库、不会返回。
- 身份证字段会在构建快照时被替换为脱敏值。
- 可在主程序 `settings.py` 中直接替换白名单，不需要修改业务代码。

### 7.7 取消公示

- 取消只改状态，不删除数据。
- 公开列表、详情、市州选项都强制 `status=PUBLISHED`。
- 取消后门户立即不可见。
- CMS 管理端仍可审计并重新公示。

## 10. 并入主程序

### 10.1 基本步骤

1. **只复制 `selection/`** 到主程序的 `backend/` 下（和 `apps/` 同级）。
   **不要复制** `config/`、`manage.py`、`db.sqlite3`，否则会覆盖主程序的 settings/urls/数据库配置。
2. 在主程序 `backend/config/settings.py` 的 `INSTALLED_APPS` 中加入 `"selection"`。
3. 在主程序 `backend/config/urls.py` 中注册（必须在读取 `api.urls` 之前）：

```python
from selection.api import register_routes as register_selection_routes

# 放在其它 api.add_router(...) 之后
register_selection_routes(api)
```

接口会挂在 `/api/v1/selection/...`，并复用主程序的 JWT、统一信封和错误处理。

如果不想改主程序 `api`，也可以单独挂载：

```python
path("api/selection/", include("selection.urls")),
```

4. 安装依赖：

```bash
python -m pip install "django-ninja>=1.6,<2.0" "openpyxl>=3.1,<4"
```

> 注意：主程序成员5使用 `from ninja import Status`，要求 django-ninja >= 1.6；不要把版本固定回 1.3，否则会降级依赖并导致主程序启动失败。

5. 执行迁移：

```bash
python manage.py migrate
```

会创建 7 张 `sel_*` 表（6 张遴选评分表 + `sel_publicity` 公示表），重复执行安全。

### 10.2 适配器与配置

并入后默认 `SELECTION_*=auto`，无需改业务代码：

| 能力 | 独立演示 | 并入主程序（auto） |
