## 3. 数据库创建与 migrate 流程

1. 创建 MySQL 库（compose 会自动建）：

   ```sql
   CREATE DATABASE football CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   ```

   （docker-compose.yml `db` 服务默认 `MYSQL_DATABASE: football`、`utf8mb4` 字符集）

2. 配置 `backend/.env` 的 `DATABASE_URL`（格式见上表；密码中 `@`/`:` 直接写原字符，勿做百分号编码——此前已发生 `%40` 导致 1045 访问拒绝的问题）。
3. 建表（只建结构，不写业务数据）：

   ```powershell
   cd backend
   python manage.py migrate
   ```

   迁移共 14 个（9 个 app），全部幂等；重复执行输出 "No migrations to apply"。结构验收基准：22 张业务表、28 外键、13 唯一约束（此前 MySQL 实库验收已通过，此处不重复验收）。
4. 建表与数据初始化职责分离：**migrate 只负责表结构；正式数据一律走 `init_base_data`（第 4 节），禁止用 seed_demo.py 作为正式初始化**（它只产出演示数据与弱密码演示账号）。

## 4. init_base_data 初始化

来源：`backend/apps/infra/management/commands/init_base_data.py`（提交 5daf067）。

### 4.1 参数

```
python manage.py init_base_data                 # 默认：全阶段只读预览（绝不写入，即使提供了 CSV）
python manage.py init_base_data --phase <名> --execute
  --phase 可选：all | dict_types | regions | schools | dict_items | material_types
  --regions-csv 路径       # 阶段 regions
  --schools-csv 路径       # 阶段 schools
  --dict-items-csv 路径    # 阶段 dict_items
  --material-csv 路径      # 阶段 material_types
python manage.py init_base_data [--phase <名>] --verify [--strict]
  # 只读验收：全程仅查询、不修复；--phase 限定检查范围；
  # 退出码 0=通过，1=存在 ERROR（--strict 时存在 WARN 也为 1）；INFO 不影响退出码
  # 注意：--strict 仅与 --verify 组合生效，单独使用时被忽略（走预览模式）
```

### 4.2 CSV 格式（utf-8，兼容 Excel BOM；多余列忽略）

| 阶段 | 列 | 唯一键 | 前置 |
|---|---|---|---|
| dict_types | 无 CSV（内置 5 骨架：team_category/position/coach_level/guardian_relation/school_type，名称为建议值） | code | 无 |
| regions | `code,name,level,parent_code,sort_order,is_active` | code | 按 level 升序自动排序（父先子后）；省级 level=1 不得有 parent_code |
| schools | `name,school_type,region_code,code,address,is_active` | (name,region)，code 可空唯一 | region_code 必须已导入；school_type 取值 PRIMARY/JUNIOR/SENIOR/NINE_YEAR/COMPLETE/MIDDLE_VOC |
| dict_items | `type_code,value,label,sort_order,is_active,ext_json` | (type,value) | type_code 必须已存在；ext_json 为合法 JSON 对象 |
| material_types | `code,name,applies_to,is_required,need_audit,allow_multiple,allowed_ext,max_size_mb,sort_order,is_active,remark` | code | applies_to 取 PERSON/TEAM，双归属写 PERSON,TEAM |

### 4.3 幂等与保护

- 按唯一键 `get_or_create`：已存在的行一律**跳过**，不覆盖人工修改；可安全重复执行。
- 缺 CSV 明确跳过并记录，不编造数据。
- 行级保存点：单行失败（含数据库级错误）只回滚该行并计入失败报告，不污染整批。

## 5. 预览检查与 --execute 时机

1. 先跑预览（默认模式），逐项核对输出：目标库（`SELECT DATABASE()`/版本）、当前各表行数、每行"新建/跳过"标记。
2. **允许 --execute 的条件**（全部满足）：
   - 预览中"新建"清单与正式数据源一致（无意外行）；
   - 字典类型 5 骨架的中文名称已经人工确认（预览中标注"名称为建议值"）；
   - 学校 `school_type` 的 6 编码对应的字典 label 已确认（当前 base_dict_item 未导入，接口按 DDL 编码常量校验——字典数据到位后自动切换字典校验）；
   - [待确认] 正式区划/学校 CSV 已由负责人签发。
3. 执行时建议逐阶段执行（先 `--phase dict_types`，再 regions → schools → dict_items → material_types），便于定位问题；`--phase all` 会按固定顺序全跑。

## 6. 初始化结果与失败核对

命令尾部输出汇总报告：

```
== 初始化报告 ==
  dict_types       新增=5 跳过=0 失败=0
  regions          新增=N 跳过=M 失败=K | 失败明细: 行12[XXX]:parent_code 'YYY' 不存在(父级须先导入)
  ...
  合计: 新增=A 跳过=B 失败=C
```

- **失败明细**含 CSV 行号、唯一键、原因，可直接回改 CSV 后重跑（幂等，已成功的行自动跳过）。
- 核对方式：失败=0 且 新增数与数据源行数一致 → 完整导入；失败>0 → 只需修复失败行重跑。
- 行数复核：`python manage.py init_base_data`（预览模式）首屏的"当前行数"应等于数据源行数合计。
- 完整性自动验收：`python manage.py init_base_data --verify`（已实现，只读）。检查项与分级：ERROR=违反冻结约束/已确认规则（区划层级与父子、school_type 6 编码、applies_to、引用存在性）；WARN=可疑但合法（父区划停用、学校空串 code、骨架字典缺失、字典项挂骨架外类型、层级覆盖缺口）；INFO=空表提示。`--strict` 让 WARN 也返回退出码 1。**验收只报告不修复**——修复需人工按报告定位后处理。

## 8. 新环境初始化 vs 已有环境补齐

| 场景 | 步骤 |
|---|---|
| 新环境（空库） | ① 配 `.env` → ② `migrate` → ③ `init_base_data` 预览 → ④ 逐阶段 `--execute` → ⑤ 结果核对（第 6 节） → ⑥ 创建正式管理员 [待确认方案] |
| 已有环境补齐（如只补字典项/材料类型） | 直接跑对应 `--phase ... --execute`；幂等机制保证已存在行跳过，不覆盖人工修改；无需重跑 migrate（无新迁移时） |
| 已有环境验证 | 预览模式即只读巡检（目标库+行数+缺失项） |

## 9. 安全注意事项与常见失败处理

**安全**：
- 生产必改：`DJANGO_SECRET_KEY`、`JWT_SECRET`、`CRYPTO_KEY`（32 字节 base64）、`ALLOWED_HOSTS`、`CORS_ORIGINS`、`DJANGO_DEBUG=false`、MinIO `MINIO_ACCESS_KEY/SECRET_KEY` 且 `MINIO_SECURE=true`。
- `.env` 已被 gitignore，禁止入库；多实例必须配 `REDIS_URL`（否则令牌撤销/限流不共享）。
- 日志内置 `SensitiveLogFilter` 脱敏（settings.py LOGGING），勿在部署层把请求体打进访问日志。
- seed_demo.py 产出弱密码演示账号，**禁止在生产执行**。

**常见失败**：
| 现象 | 原因与处理 |
|---|---|
| MySQL 1045 访问拒绝 | 密码被误做 URL 编码（`%40`）；本 settings 不解码，`@` 直接写原字符 |
| `Unknown database` | 先执行 CREATE DATABASE（第 3 节），检查 `DATABASE_URL` 库名 |
| migrate 报 W163/W046 告警 | SQLite 端不落 db_comment 的预期告警，MySQL 端生效，可忽略 |
| CSV 行报 `parent_code 不存在` | 区划父级未导入或 CSV 行序混乱；命令已按 level 排序，检查 parent_code 拼写 |
| CSV 行报 `school_type 非法` | 只允许 6 个 DDL 编码（见 4.2 表） |
| `CSV 文件不存在` | 检查 `--regions-csv` 等路径（相对路径以 backend 目录为基准） |
| 429 RATE_LIMITED | 触发限流；调整 `THROTTLE_*` 或等待窗口 |
| git push SSL 断连 | 代理上游抖动，稍候重试；勿改 git config |
