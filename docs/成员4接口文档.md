## 1. /base-data 基础数据路由契约（21 条）

模块：`backend/apps/persons/api.py`（router tags=["base-data"]，L46）、`persons/schemas.py`、`persons/services.py`。

### 1.1 总则

- 鉴权：JWTAuth；响应统一信封 `EnvelopeOut`（读=`ok`/分页，写返回对象，删=`action_result(true, id)`）。
- 权限：21 个权限点导入期 `register_operation`（api.py L50-73）。查询类 8 个 = ALL_ROLES（与 accounts dictionaryOptions 授权惯例一致，api.py L4-5）；写操作 13 个 = 仅 ADMIN。
- 审计：写操作统一 `audit_state()`（动作 `baseData.<域>.<操作>`，object_type/object_id/summary），由 AuditMiddleware 落 accounts_audit_log。
- 删除语义：Region / School / DictItem **只停用不删**（is_active=False）；DictType **无引用时物理删除、有引用 409**（api.py 模块注释 L8；services.py L322-328）。
- 分页：列表 `paginate(request, queryset, mapper=…)`；options 用 `paginate_list`（api.py L311）。

## 2. init_base_data 初始化命令契约

模块：`backend/apps/infra/management/commands/init_base_data.py`（幂等可重跑，默认只读预览）。

### 2.1 参数（8 个，L95-106）

| 参数 | 类型/默认 | 说明 |
|---|---|---|
| --phase | 默认 all；choices：all / dict_types / regions / schools / dict_items / material_types | 阶段选择 |
| --execute | store_true，缺省关闭 | 实际写入开关（缺省只预览） |
| --regions-csv | 路径 | 区划 CSV（列：code,name,level,parent_code,sort_order,is_active） |
| --schools-csv | 路径 | 学校 CSV（列：name,school_type,region_code,code,address,is_active） |
| --dict-items-csv | 路径 | 字典项 CSV（列：type_code,value,label,sort_order,is_active,ext_json） |
| --material-csv | 路径 | 材料类型 CSV（列：code,name,applies_to,is_required,need_audit,allow_multiple,allowed_ext,max_size_mb,sort_order,is_active,remark） |
| --verify | store_true | 只读验收；与 --execute 互斥，同给则 CommandError（L422-423） |
| --strict | store_true | 验收严格模式：存在 WARN 也返回非零退出码（L412-413） |

### 2.2 预检行为与执行边界

- **默认只读预览**：打印目标库与版本（MySQL 取 DATABASE()/VERSION()，SQLite 取 sqlite_version()，L110-121）、5 张表当前行数（base_region/base_school/base_dict_type/base_dict_item/material_type，L123-129）、各阶段就绪状态与缺失项；**不带 --execute 任何阶段（含提供了 CSV 时）都不写**（docstring 约定1；预览仅 exists 探测，L195-197/L224-226/L275-277/L308-310）。
- **幂等**：按业务唯一键 get_or_create，已存在一律跳过，不覆盖人工修改（docstring 约定2；L199/L228/L279/L312）。
- **不编造数据**：regions/schools/dict_items/material_types 缺 CSV 时明确跳过并记录（L166/L207/L236/L287）。
- **依赖顺序**：阶段固定 dict_types→regions→schools→dict_items→material_types（L435）；区划按 level 升序处理（父级先于子级，L170）；学校依赖已导入区划、字典项依赖字典类型。
- **事务边界**：--execute 时每阶段整体 `transaction.atomic()`（L438-442）；行级独立保存点，单行失败（含数据库级错误）只回滚该行并记入失败报告，不污染整批（L131-141、L198/L227/L278/L311）。
- **退出码**（--verify）：0=通过；存在 ERROR，或 --strict 时存在 WARN → sys.exit(1)（L412-413）。
- 本命令为数据级操作：不执行迁移、不修改冻结结构。

### 2.3 导入校验规则

- CSV 读取：utf-8-sig（兼容 Excel BOM）；多余列丢弃；缺失值按空串（L78-89）。
- 布尔解析：TRUE_SET = {1, true, yes, on, 是, y}，大小写不敏感（L69-75）。
- dict_types：仅 6 个骨架 code（team_category/position/coach_level/coach_category/guardian_relation/school_type，L54-61）；name 为建议值，可在执行前人工确认/修改。
- regions：code/name 必填；level ∈ {1,2,3}；省级（level=1）不得有 parent_code；非省级必须提供；parent_code 须已导入（L174-189）；唯一键 code。
- schools：name 必填；school_type ∈ SCHOOL_TYPE_CODES 6 值（PRIMARY/JUNIOR/SENIOR/NINE_YEAR/COMPLETE/MIDDLE_VOC，L64）；region_code 须已存在（L213-220）；唯一键 (name, region)，code 可空唯一。
- dict_items：type_code 须存在；value/label 必填；value 须匹配 `^[A-Za-z0-9][A-Za-z0-9_-]{0,49}$`（L46）；ext_json 须为合法 JSON 且存对象非字符串（L266-272）；**跨行同 (type_code, label) 重复 → CommandError 整批拦截**（L243-252）；唯一键 (type, value)。
- material_types：code/name 必填；applies_to ∈ {PERSON, TEAM}；缺省 allowed_ext=jpg,jpeg,png,pdf、max_size_mb=10、need_audit=True（L293-307）；唯一键 code。

### 2.4 只读验收规则（--verify，L319-413）

分级口径：ERROR=违反冻结约束或已确认服务层规则；WARN=可疑但合法/依赖未确认清单；INFO=空表提示。

| 域 | 检查项与级别 | 依据 |
|---|---|---|
| dict_types | 空表 INFO；骨架 6 code 缺失 WARN（名称/清单未最终确认，不判硬错） | L327-333 |
| regions | level 非法 ERROR；父引用悬空 ERROR；省级有父 ERROR；非省级缺父 ERROR；父级 level≠level-1 ERROR；父级已停用 WARN；层级覆盖缺口（存在 level=3 缺 level=2 / 存在 level=2 缺 level=1）WARN | L336-363 |
| schools | school_type 非法 ERROR；空串 code 占唯一键 WARN；区划引用悬空 ERROR | L366-378 |
| dict_items | 字典类型引用悬空 ERROR；挂骨架外类型 WARN（正式清单未确认，人工确认级） | L381-392 |
| material_types | 空表 INFO；applies_to 非法 ERROR | L395-400 |

实现注记：验收用全表预加载构建 pk 映射而非 select_related——JOIN 会把悬空父级引用行从结果集丢弃导致防御检查失效（L338/L368/L383 注释）。

## 6. 通用规范（联调成员4接口必读）

> 依据：`backend/apps/common/`（errors.py / envelope.py / pagination.py / permissions.py / authentication.py）与各域 services，2026-10-27 快照。本章描述的是**当前代码实际行为**；其中数据范围（6.8）明确区分当前行为、待业务确认与未来建议三段，未批准方案不得当契约使用。

### 6.1 认证与令牌

- 除后文标注 `auth=None` 的公开端点外，成员4域全部接口要求认证：请求头 `Authorization: Bearer <JWT>`。
- 令牌校验失败按原因返回：无效/格式错误 → 401 `UNAUTHENTICATED`；过期 → 401 `TOKEN_EXPIRED`；已登出吊销 → 401 `TOKEN_REVOKED`（common/authentication.py）。
- 权限判定在 `common/permissions.py require()` 中统一执行，拒绝链为：未认证 → 401 `UNAUTHENTICATED`；账号停用 → 403 `FORBIDDEN`；当前角色不在权限点登记角色内 → 403 `FORBIDDEN`（含具体说明）。权限点→角色登记表以 `register_operation()` 注册为准（成员4域 50 个权限点见 §5）。
- 登出仅吊销当前令牌；改密成功后旧令牌吊销、首次登录强制改密（accounts 域行为，联调时前端需处理 401 重新登录流程）。

### 6.2 统一响应信封

成功与失败均为统一 JSON 信封（common/envelope.py，契约 2.1；禁止错误也返回 200）：

```json
{ "code": "OK", "message": "", "data": { } }
```

- 成功：`code="OK"`，`data` 为业务载荷（对象、数组或分页结构）。
- 失败：`code` 为 6.3 错误码，`message` 为可读说明，`data` 可选（常为字段级明细）。
- 参数校验失败（ninja/pydantic）→ 400 `INVALID_ARGUMENT`，`data=[{"field": "...", "reason": "..."}]`（common/errors.py `_ninja_validation_details`）。
- 请求多余字段：Schema 为 Strict 风格，多余字段同样落入 400 `INVALID_ARGUMENT`（profileConfirm 等测试断言）。
- 未处理异常 → 500 `INTERNAL_ERROR`；`Http404`/`ObjectDoesNotExist` → 404 `NOT_FOUND`（框架兜底 handler，errors.py L163-193）。

### 6.4 分页

- 请求参数：`page`（从 1 开始，最小 1）、`pageSize`（最小 1，**默认 20，最大 100**）；均为可选 Query。
- 响应 `data` 结构（common/envelope.py `page()`）：`{"items": [...], "page": <当前页>, "pageSize": <页大小>, "total": <总数>}`。
- 列表类接口（regionList/schoolList/dictTypeList/dictItemList/peopleList/teamList/memberList/materialList）均经 `common/pagination.paginate()`，排序口径见各接口小节。
- 非分页数组直出的例外：`POST /people/search`（≤20 条）、`GET /me/teams`、`POST /teams/{id}/members/search`（≤20 条）。

### 6.5 乐观锁（version）

- 版本值为**派生值**：`updated_at` 的 UTC 微秒数（`updated_at.timestamp()*1e6`），无独立数据库列；<2^53 在 JS number 中无损，前端原样回传即可。
- 规则：写路径（PUT/DELETE）`version` 必填——缺失或非法 → 400 `INVALID_ARGUMENT`；与当前派生版本不一致 → 409 `VERSION_CONFLICT`（响应 data 含当前版本）。
- 校验入口：persons/services.py `ensure_version()`；materials/teams 采用同款派生与校验口径。
- 删除类接口 `version` 走 Query（如 `DELETE /people/{id}?version=`、`DELETE /materials/{id}?version=`）。
- 写路径禁用 `queryset.update()` 绕过 auto_now（保证派生版本单调演进，B4 口径）。

### 6.6 软删除

- 业务主档（Person/Team/Material/FileRecord/Region/School/DictType/DictItem 等）删除均为软删（`is_deleted`/`deleted_at`），不物理删除。
- 默认查询 manager（ActiveManager 类语义）固定排除已删行 → **软删对象对一切接口一律 404**（含 pk/team_no 双寻址、归属校验）。
- 唯一性查重的差异（联调注意）：人员证件号查重**含软删行**（重复 409 不复活）；组织 code 复用会复活原节点（accounts 域）。各接口差异见对应小节。
- 区划/字典类型/字典项的删除为"停用"语义（DELETE 端点），启用中存在下级/挂项时 409 `STATE_CONFLICT`。

### 6.7 审计留痕

- 管理端写操作与本人档案操作写 `AuditLog`（action 形如 `person.self_update`、`person.self_confirm`）；人员档案字段级变化写 `PersonChangeLog`（UPDATE 记录 field_changes，仅含实际变化字段）。

### 10.1 四层访问校验链（can_access，services.py:251-273 实证）

认证 → 权限点（ALL_ROLES 放行）→ 数据范围 → **对象归属（第 4 层，`can_access` 按序短路：本人 → ADMIN → 归属校验器，任一通道通过即放行；全部不通过一律拒绝）**：

1. **上传者本人通道**：谁上传谁可读（与业务归属无关）；
2. **ADMIN 全局通道**：A′ 一期数据范围仅 ADMIN 全量；
3. **业务归属校验器通道**：`register_owner_verifier(owner_type, verifier)` 由各业务域注册（services.py:54-55）——已注册 **PERSON**（persons/apps.py:20，人员校验=本人或 ADMIN）、**TEAM**（teams/apps.py:20，归属对象存在性 + ADMIN，落经 `teams.verify_team_owner`）两者为 T4-06 接入（`16618c9`）；另有 **ENROLLMENT**（enrollments/apps.py:16，成员3 报名域注册，规则以成员3 域文档为准）；**PROVINCE_REVIEWER/MATCH_RECORDER 等特权角色不再凭角色放行**，PERSON/TEAM 私有附件必须通过归属裁决。**deny-by-default**：未注册校验器的 owner_type（MATCH/CONTENT/RESOURCE/IDENTITY_CHECK 等）或校验器抛出 ApiError → 一律 False → 403，不默认放行。

统一入口 `get_record(account, file_id)`（services.py:276-282）：不存在/软删 → 404 NOT_FOUND；`can_access` 不通过 → **403 FORBIDDEN"无权访问该文件"**（field=fileId"超出数据范围"）。

### 10.2 上传与绑定（先传后绑）

#### POST /files — 上传单个文件（fileUpload）

- Body：multipart（文件必传）+ `ownerType`（PERSON/TEAM）+ `ownerId`（可选）+ `category`（**必填**，合法类别与扩展名清单见 §11.4，batch 同口径）。
- **空归属角色兜底**（services.py:66-74）：ownerId 缺省时仅 **ADMIN/PROVINCE_REVIEWER/MATCH_RECORDER** 可传无主文件，普通账号 → 403 FORBIDDEN"文件归属对象尚未创建"（防借空归属绕过校验）——前端新建人员先传头像走此通道，创建时经 `avatarFileId` 回填绑定。
- 非空归属：`_check_owner` 按归属校验器裁决（未知 ownerType → 400 INVALID_ARGUMENT）。
- 响应：FileRecord 元数据（含 file_id；**无 url 直链字段**——storage.py 契约 5：私有文件无直链，mock 的 `record.url` 演示逻辑不得采用）。

#### POST /files/batch — 批量上传（fileBatchUpload）

同单文件口径的批量形态，但 **ownerId 必填**（`Field(..., min_length=1)`，api.py:52），空归属的角色兜底仅适用于单文件接口；批量上限与逐文件错误隔离以成员2 域实现为准（成员4 联调场景通常单文件）。

### 10.4 签名展示地址（main 扩展，3 条）

#### GET /files/{file_id}/signed-url — 签发短期展示地址（fileSignedUrl）

- 用途：`<img>` 等无法携带 Authorization 头的场景；认证 + `get_record` 归属裁决后签发（api.py:158-168），写 AuditLog（file.signedUrl）。
- 签名机制（services.py:312-336）：HMAC-SHA256 绑定 **fileId + variant + 过期时间**，`hmac.compare_digest` 恒时比较；**HTTP 端点不暴露 ttl_seconds 参数**（固定默认 TTL，settings `FILE_TICKET_TTL_SECONDS`，300 秒），外部无法放大有效期；泄露的旧地址到期自动失效。
- 响应：`{url, expiresAt, variant}`（services.py:332-336；url=`/api/v1/public/files/{id}/{variant}?exp=..&sign=..` 形态，`exp` 仅是 URL 查询参数名）。

#### GET /public/files/{file_id}/content 与 /thumbnail — 免认证签名读取（auth=None）

- 校验链：`verify_signature`（services.py:350-360，三分支均 403——variant 非法"展示地址无效" / `expires_at < now` "展示地址已过期" / `hmac.compare_digest` 不匹配"展示地址签名无效"）→ `get_public_record`（services.py:363-367，经默认 manager 排除软删行 → 404）。
- 响应：content 走原 content_type；thumbnail 固定 image/jpeg、无缩略图 → 404"该文件没有缩略图"；均 **Cache-Control: private, no-store**。
- **portal 专用长期地址**：`services.portal_image_url(file_id)`（services.py:339-346）签发默认 **7 天** TTL（settings `PORTAL_FILE_TICKET_TTL_SECONDS=604800`），供 events 门户公开投影（`96b63fc`）组装 imageUrl 使用；docstring 明言**调用方必须先确认资源已发布**——该约束为调用方自律，无代码强制（见 10.6 风险 1）。

2. **服务层强制规则不建唯一索引**：R1-R5（teams/models.py 模块注"6 条服务层唯一规则不建数据库唯一索引"）与 R6（materials/models.py 模块注；idempotency_key 唯一索引兜底重复提交）——跨行/条件唯一（如"队内现役唯一"）无法用普通唯一索引表达。
3. **乐观锁双轨**：Person/Team/PersonMaterial/TeamMaterial **无 version 列**，version = updated_at UTC 微秒派生（B4，`ensure_version` persons/services.py:605；PUT/DELETE 必填、缺失 400、过期 409）；attachments FileRecord 为**独立 int version 列**（`bump()`/`check_version`，common/versioning.py）。两套并存，接口侧 version 语义统一按 §6.5。
4. **软删口径分层**：attachments 由默认 manager 排除软删行（models.py:60 `objects = ActiveManager()`，读取通道天然 404）；persons/teams/materials 无自定义默认 manager，软删过滤由服务层在查询处显式承担（如 teams `_team_queryset` 固定 is_deleted=False）；效果一致——软删对象一律 404（§6.6）。基础数据（Region/School/DictType/DictItem/MaterialType）只停用不软删。
5. **禁止物理删除 / append-only 清单**：team_member、team_coach、team_transfer（历史留痕）；person_change_log、sensitive_access_log、material_audit_log、material_file_version（append-only）。例外：附件批量上传整批失败回滚会物理删除当批 FileRecord 元数据并清理已落地对象（services.py:242-247）。
6. **外键与索引约定**：业务 FK 全部 `on_delete=PROTECT`、列上 `db_index=False`，索引按冻结名保留在 Meta.indexes；两个扩展档案 OneToOne 为 `db_constraint=False`（DB 层由 0002 迁移显式建 FK CASCADE）；多态引用（material_kind+material_id）与文件引用（`*_file_id` 字符串逻辑引用文件服务，不存 URL）均无 FK，完整性由应用层保证。
7. **敏感字段三件套**：cipher（AES 密文）+ hash（SHA256+盐，等值查重）+ masked（掩码展示）；变更日志只写掩码（PersonChangeLog.field_changes）。
8. **字典逻辑引用**：Team.category_code、School.school_type、AthleteProfile.grade_level/position_code、TeamMember.position_code、AthleteProfile.guardian_relation、CoachProfile.coach_level 等 CharField 指向字典项，无 FK——字典项缺失/停用时的接口行为以各接口章节为准（§1/§7/§8）。

### 13.1 PUT /api/v1/enrollments/{enrollmentId}/players/{rosterId}/qualification — 资格操作

| 项 | 内容 |
|---|---|
| 权限点 | `rosterQualify`（register_operation，**仅 TEAM、UNIVERSITY**；CITY/PROVINCE_REVIEWER 只读报名，ADMIN 不开放——未注册角色经 require() 返回 403 FORBIDDEN） |
| 数据范围 | 逐请求 `scope.get_enrollment`：TEAM/UNIVERSITY 仅自身范围名单（越权 403 DATA_SCOPE_DENIED；不存在/不可见 404 NOT_FOUND） |
| 请求体 | `{"action": "CONFIRM"\|"REJECT"\|"EXCLUDE"\|"REVOKE", "version": <int 必填>, "reason": <string，REJECT/EXCLUDE/REVOKE 必填，CONFIRM 不需要>}`；action 非法由 pydantic Literal 校验拒绝（422，校验错误格式）；reason 缺失/空白由服务层判定（422 BUSINESS_VALIDATION_FAILED） |
| 状态机 | CONFIRM：非 EXCLUDED 均可，已有效确认时幂等 no-op（不追加日志、不改版本）；REJECT：→DISQUALIFIED+清凭证；EXCLUDE：→EXCLUDED（资格接口**不可逆**，四操作对 EXCLUDED 行均 409）；REVOKE：仅 QUALIFIED+有效凭证，清凭证**不改** qualification_status；**D-2（2026-10-29 批准实施）：`enrollment.status==APPROVED` 时四操作全部 409 STATE_CONFLICT（`data[0].reason=ENROLLMENT_APPROVED`），禁令优先于幂等 no-op；REJECTED/WITHDRAWN 不在禁令内** |
| 事务与并发 | `transaction.atomic` + `select_for_update` 行锁 + `check_version`（冲突 409 VERSION_CONFLICT）；状态更新与日志写入同事务；日志追加式（append-only，独立于 ReviewRecord） |
| 响应 | `data`: `{"qualificationStatus", "confirmedAt", "confirmedBy"}`（confirmedAt/confirmedBy 为当前凭证，无凭证时为 null/空串） |
| 审计 | 中间件 `audit_state` 记 `enrollment.roster.qualify`（object_type=RosterItem，object_id=rosterId） |

**错误码**：UNAUTHENTICATED 401 / FORBIDDEN 403 / DATA_SCOPE_DENIED 403 / NOT_FOUND 404 / VERSION_CONFLICT 409 / STATE_CONFLICT 409 / BUSINESS_VALIDATION_FAILED 422 / INVALID_ARGUMENT 400（框架兜底）。

**终审联动（本端点不抛 422）**：报名终审（province APPROVE）经 `double_track_issues` 硬门槛要求有效凭证（`confirmed_at` 与 `confirmed_by` **同时**有效）；`qualification_status=QUALIFIED` 本身不构成凭证；REVOKE 后终审必拒（422 QUALIFICATION_NOT_CONFIRMED）。换人（rosterUpdate 改 athleteId）即清凭证并须重新确认。
