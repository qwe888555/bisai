### 2.2 Service 关键行为（backend/apps/persons/services.py）

- **数据范围**：`apply_person_scope()` —— **角色门禁与数据范围为两层独立机制**：查询权限点 `_PERSON_QUERY_ROLES`（api.py:405）含 ADMIN/UNIVERSITY/CITY/PROVINCE_REVIEWER/TEAM（CITY/PROVINCE_REVIEWER 为审核场景预留）；范围层（services.py:441-547，第三批 2026-10-29 已实施）：ADMIN 全量或按组织子树；**UNIVERSITY 本校**（子树内学校类节点 code ↔ Person.school.code）；**TEAM 本队**（绑定球队 CURRENT 正式成员/教练双路径 Exists）；CITY/PROVINCE_REVIEWER 及无有效范围者一律 403 DATA_SCOPE_DENIED（本批继续拒绝，口径记录见成员4接口文档 §6.8 A1–A5）。
- **创建**：idNumber 服务层必填；SHA 哈希查重**含软删行**（重复 409 不复活）；身份证 GB11643 解析出生日期+性别；person_no=`P+年份4位+8位id` 共 13 字符回填；ChangeLog 记 CREATE。
- **更新**：version 校验（`ensure_version` 不一致 409）；**全量替换**+可选缺省保留；diff 留痕 ChangeLog（日期转 isoformat）；idNumber 不接受修改；education **已持久化**（E1，未传=保留原值、传值含空串=覆盖）；coachCategory 仍声明接受但不持久化、不参与审核失效（字典 E2 底稿已提交 e8f9178，正式签发待确认）。
- **删除**：version 校验 + TeamMember(CURRENT)/TeamCoach 存在即 409 挡 → 软删 + ChangeLog DISABLE。
- **多身份（方案 C，B1 已批）**：`PersonCreate.kinds` Field(min_length=1,max_length=2)，多类别/重复 400；冻结单值列 `person_category` 存提交首项（主类别）；AthleteProfile/CoachProfile **行存在性=完整类别集合事实源**；`_apply_kinds` 先校验后变更——移除类别时 profile 行有业务数据（AthleteProfile 6 字段/CoachProfile 4 字段）→ 409 整体拒绝，空行才删；update 尾部重查对象保证 kinds 合成一致（annotate 快照过期教训）。
- **乐观锁（B4 已批）**：`person_version=int(updated_at.timestamp()*1e6)`（UTC 微秒，<2^53 无损）；写路径禁用 queryset.update（绕过 auto_now 盲区）。
- **响应映射**：`kinds`=[person_category]+profile 行合成，固定 ATHLETE→COACH；`schoolOrgId=str(school_id)`（临时口径，见 D1）；`reviewStatus`=audit_status 直出（含前端未定义的 DRAFT 值）；`education` **输出真实列值**（E1：Person.education，可选自由文本 ≤100）；`coachCategory` 仍**不输出**；`maskedStudentNumber`←student_no 脱敏；idNumber 只写不回显。
- **学校解析**：`_resolve_school()` 隔离函数，暂按 **School 主键**解析（隔离待 A′，仅改此函数）。

### 2.3 头像与文件链路（backend/apps/attachments + persons）

- 先传后绑：POST `/files` 的 `ownerId` 可选（空值走角色兜底 ADMIN/PROVINCE_REVIEWER/MATCH_RECORDER，否则 403）；person create/update 携带 `avatarFileId` → `_bind_avatar` 以 `FileRecord.objects.filter(pk=str(id), owner_type="PERSON").update(owner_id=...)` 回填（FileRecord 主键为字符串）。

## 4. 契约分类结论

### A 类（前端明确 → 后端已适配/可直接推进，无需再确认）

1. kinds 一人一身份（问题 11 方案 B，2026-10-30 批准）：PersonCreate 必填限 1 项；PersonUpdate 可选，未传=保留现有身份，传值限 1 项；历史双身份经 ORM 构造测试。
2. 头像先传后绑 avatarFileId → 已实现（含空 ownerId 角色兜底）。
3. DELETE version 走 query → 已实现。
4. 列表 keyword/kind/reviewStatus 过滤与分页 → 已实现（keyword=full_name icontains，kind 按 profile 行存在性）。
5. search POST 返回数组（沿用 mock 上限 20）→ 已实现。
6. identityApi GET `/identity-checks` 路径 → 别名已实现。
7. gender 三值 MALE/FEMALE/UNSPECIFIED → 名称映射已实现。
8. reviewStatus 直出 audit_status → 已实现（DRAFT 值前端类型未定义，前端补类型即可，非后端问题）。
9. row.version 随 PUT/DELETE 提交 → 已实现（B4 派生 version）。
10. idNumber 仅创建、编辑置空 → 后端 PersonUpdate 不接受 idNumber，一致。
