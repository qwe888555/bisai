## 二、输入校验

### 2.1 owner_type
- 仅接受 `"PERSON"` / `"TEAM"`，大小写敏感
- 非法值 → `ApiError(INVALID_ARGUMENT, "ownerType 仅支持 PERSON/TEAM", [{"field":"ownerType","reason":"不在枚举范围内"}])`

### 2.2 owner_ids
- 类型：仅 `list` / `tuple`，否则 400
- 元素：必须为正整数；拒绝 `bool`、`float`、`str`（含数字字符串）
- 任一非法元素 → 整体 400 拒绝（不跳过合法项继续查询）
- 去重保序（首次出现保留）
- 空列表/元组 → 400

### 2.3 type_codes
- 类型：仅 `list` / `tuple`，否则 400
- 逐元素 `str(orig).strip()`；空串丢弃
- 去重保序（首次出现保留），同时保留 `(原始值, 规范化值)` 对
- 规范化后无有效码 → 400

## 三、类型批量预检

- 遍历去重后的码列表，对每个码查询 `MaterialType.objects.filter(code=code).first()`
- **不检查** `is_active`（历史材料可查）
- 两种问题均收集（不短路），全部遍历后若 `problems` 非空则统一抛 400：
  - 类型不存在 → `{"field":"type_codes","value":<原始值>,"reason":"材料类型 <code> 不存在"}`
  - `applies_to != owner_type` → `{"field":"type_codes","value":<原始值>,"reason":"材料类型 <code> 不适用于 <owner_type> 归属"}`
- `problems` 顺序 = 去重后输入顺序；`value` 保留**原始输入值**（非 strip 后值）

## 四、数据范围

由函数本身三重执行，不依赖调用方：

1. `scope = _material_scope(account)` — 按角色返回 `(school_codes, team_ids)`：
   - ADMIN → `(None, None)` 全库
   - UNIVERSITY → `(本校组织子树 codes, None)`；无有效组织范围 → 403
   - TEAM → `(None, 本队 team_ids)`；空绑定 → 403
   - 其余角色 → 403

2. 对每个**存在的**归属对象调用 `_ensure_owner_in_scope(owner, scope)`：
   - TEAM 范围：要求 `isinstance(owner, Team) and owner.pk in team_ids`，否则 403
   - 学校范围：要求 `owner.school.code in codes`，无学校归属 → 403（deny-by-default）

3. 查询集经 `_apply_scope(queryset, owner_type, scope)` 二次过滤：
   - TEAM 范围 + `owner_type="PERSON"` → `queryset.none()`
   - TEAM 范围 + `owner_type="TEAM"` → `team_id__in=team_ids`
   - 学校范围 → 按 `person__school__code` 或 `team__school__code` 过滤

**TEAM 查询 PERSON 材料的实际行为**：在第 2 步 `_ensure_owner_in_scope` 中，因 `isinstance(Person_instance, Team)` 为 `False`，**明确抛出 `DATA_SCOPE_DENIED`**（403），不会到达第 3 步的 `_apply_scope`。对应测试 `test_scope_team_person_material_denied` 断言 403，与实现一致。

## 五、返回字段与排序

### 5.1 返回结构
```python
{"items": [...], "missing_owner_ids": [...]}
```

### 5.2 items 恰好 8 字段

| 字段 | 类型 | 来源 |
|---|---|---|
| `owner_id` | int (BIGINT) | 材料归属对象主键 |
| `material_id` | int | 材料主键 |
| `type_code` | str | `MaterialType.code` |
| `status` | str | 材料状态枚举值 |
| `need_audit` | bool | `MaterialType.need_audit` |
| `allow_multiple` | bool | `MaterialType.allow_multiple` |
| `file_id` | int | 关联文件 ID |
| `updated_at` | str | `datetime.isoformat()` (ISO 8601) |

### 5.3 排序

**契约排序规则**：`owner_id ASC → type_code ASC → updated_at DESC → material_id DESC`

**当前实现方式**：使用 Python 内置 `sorted()`，排序 key 为四元组：

```python
key=lambda m: (
    getattr(m, owner_field),              # owner_id ASC（升序，正值）
    m.type.code,                          # type_code ASC（升序）
    -m.updated_at.timestamp() if m.updated_at else 0,  # updated_at DESC（取负实现降序）
    -m.pk,                                # material_id DESC（取负实现降序）
)
```

前两个排序键直接使用原始值实现 ASC；后两个排序键通过取负（`-timestamp()`、`-pk`）实现 DESC。当 `updated_at` 相同时，由 `material_id` 的负值继续比较，保证 material_id DESC 的兜底排序。

### 5.4 missing_owner_ids 语义
- 定义：输入归属 ID 中**无有效材料记录**者
- 顺序：按去重后的输入顺序
- 去重：因 `parsed_ids` 已去重，`missing_owner_ids` 天然无重复
